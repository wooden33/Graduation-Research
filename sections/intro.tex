\section{INTRODUCTION}

Automated unit test generation plays a critical role in improving software reliability and reducing developer effort. Traditional techniques, such as symbolic execution and search-based software testing (SBST), have made substantial progress in systematically exploring input spaces and maximizing structural coverage~\cite{cadar2008klee, evosuite, mcminn2011, randoop}. However, these approaches often face fundamental limitations in scalability and in handling complex program semantics: They struggle to capture implicit preconditions that arise from intricate object states and inter-procedural interactions, where the conditions required to reach a target path are established outside the local method scope through sequences of prior method calls~\cite{baldoni2018}.

Recent advances demonstrate that large language models (LLMs) can directly synthesize executable unit tests, significantly alleviating manual effort~\cite{yuan2024manualtest, chen2024, chu2025}. To handle complex methods and improve coverage, subsequent research mainly pursues two directions. The first is \textit{feedback-driven refinement}: CoverUp~\cite{chen2024} iteratively targets untested regions using dynamic coverage analysis, while YATE~\cite{konstantinou2025yate} repairs failing tests to enhance validity. The second direction emphasizes \textit{structural decomposition and path sensitivity}. %To simplify complex logic, 
HITS~\cite{wang2024c} prompts LLMs to decompose methods into fragments. Advancing this using program analysis, SymPrompt~\cite{wang2024c} extracts branch constraints from Control Flow Graphs (CFGs), whereas Panta~\cite{gu2025a} fuses static CFG analysis with dynamic coverage feedback to identify uncovered paths. Building upon this trajectory, JUnitGenie~\cite{liao2025} achieves strict path sensitivity by isolating the minimal, path-specific context required for targeted generation.

Despite these promising results, a substantial coverage gap remains, rooted not in a lack of feedback or prompting sophistication, but in a deeper mismatch, i.e., \emph{cognitive misalignment}, between the information exposed to the LLM and what is actually required to cover complex target branches.

\ding{172} One important dimension of this misalignment is \emph{What to Satisfy}. 
In many cases, branch reachability depends on implicit preconditions scattered across long dependency chains, requiring the model to infer hidden constraints through multiple variable assignments and state transitions before it can synthesize a valid test. 
Existing approaches typically provide only the target branch structure and compress constraint inference and test synthesis into a single generation step, without any explicit intermediate output or independent verification of the inferred constraints. 
As a result, the LLM can easily skip or compress critical reasoning steps, producing tests that appear plausible but fail to satisfy the actual conditions required to reach the target branch. 
This problem becomes particularly severe when the underlying dependency chain is long or semantically complex.

\ding{173} The second dimension concerns \emph{What to Attend To}. 
Existing methods usually expose the entire method body to the LLM, even though only a small subset of statements has real data or control dependence on the target branch. 
The resulting context is therefore structurally misaligned with the branch-coverage objective: coverage-critical dependencies are diluted by irrelevant code, attention is spread across non-essential statements, and the model must reason under a representation that over-emphasizes what is visible rather than what is truly necessary. 
This not only amplifies cognitive burden, but also makes precise state construction substantially less likely. 
Even without explicit distractors, LLM performance can already degrade as context length grows~\cite{du2025contextlengthhurtsllm, wang2026intelligencedegradationlongcontextllms}; 
in branch-oriented test generation, this effect is further magnified because the relevant context is often deeply buried inside much longer method bodies.

%Taken together, these two issues suggest a systematic form of \emph{cognitive misalignment} in LLM-based unit test generation: the information shown to the model is often misaligned with the information actually needed to cover a target branch. 
%This misalignment has two complementary dimensions, namely \emph{what to satisfy} and \emph{what to attend to}.


To address this cognitive misalignment, we propose \ourmethod{}, an LLM-driven framework for automated unit test generation. \ourmethod{} explicitly tackles both dimensions of the gap, by making critical constraints explicit and concentrating the model's attention on branch-relevant program context.
First, {\textit{Constraint-Hints}} addresses the \emph{what to satisfy} dimension by making the execution conditions of uncovered paths explicit. Instead of forcing the LLM to deduce implicit constraints from raw code, this mechanism extracts path conditions and translates them into actionable guidance. It drastically reduces the model's reasoning difficulty by directly suggesting \emph{how} to satisfy a target condition—such as invoking specific setter methods to establish the required object state. By surfacing these hidden cross-method preconditions, it actively guides the LLM to construct valid initialization sequences, ensuring complex dependencies are properly addressed rather than silently skipped.
Then, \textit{coverage-driven backward slicing} addresses the \emph{what to attend to} dimension. Rather than supplying the full method body, the slicer isolates the minimal set of statements that genuinely influence an uncovered branch, including cross-method dependencies such as field initializations and setter methods. 
This restructures the prompt context around branch-relevant dependencies, preventing the model's attention from being diffused across irrelevant code. 
The slicing is triggered selectively when coverage plateaus, targeting branches that resist standard generation.
Both components are integrated into an iterative loop of generation, execution, and repair. 

\textbf{Evaluation.}
We evaluate \ourmethod{} on 14 Java projects from Defects4J v2.0.1, covering 130 classes and 2971 methods with cyclomatic complexity greater than 10. Baselines include SymPrompt, HITS, and Panta, representing complementary design philosophies.
\ourmethod{} achieves 44.41\% average branch coverage, outperforming SymPrompt (21.14\%), HITS (34.24\%), and Panta (32.32\%). 
Gains are most pronounced on logic-heavy subjects with rich cross-method dependencies: on Gson, \ourmethod{} reaches 41.24\% versus SymPrompt's 3.59\%; on Jsoup, it improves over HITS by 36.4\%.

Ablation study confirms the complementary roles of both components. 
Removing \emph{Backward Slicing} drops coverage from 44.41\% to 38.47\%, with the largest degradation on context-heavy subjects (e.g., Csv: 52.29\%$\to$24.80\%). 
Removing \emph{Constraint-Hints} drops coverage to 39.79\%, most severely on subjects with object-state dependencies (e.g., JacksonDatabind: 17.85\%$\to$9.33\%).
Finally, \ourmethod{} generalizes across backbone LLMs, achieving 44.41\% (QC3-30B), 83.47\% (QW3.5-397B), and 80.12\% (DS-V3.1), confirming that its benefit derives from restructuring branch-relevant information rather than relying on any specific model.

In summary, this paper makes the following contributions:
\begin{itemize}[leftmargin=*]
\item We identify a key limitation of existing LLM-based test generation approaches in handling implicit, cross-method constraints.
We propose \textit{Constraints-Hints}, a mechanism that makes path conditions explicit and guides LLM reasoning.
\item We introduce a coverage-driven backward slicing technique to eliminate irrelevant context and expose critical dependencies.
\item We design an iterative framework that integrates generation, execution feedback, and repair for sustained coverage improvement.
We empirically demonstrate the effectiveness of our approach on real-world software systems.
\end{itemize}
