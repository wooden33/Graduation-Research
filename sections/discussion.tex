\section{DISCUSSION}

\paragraph{Cost and Token Efficiency.}
\ourmethod{} introduces additional prompting overhead from backward slicing and constraint hint construction. Across all 3,576 requests, total token consumption reaches 221.8M input and 6.1M output tokens; however, 181.5M input tokens are served from cache due to repeated prompt structures, leaving only 40.3M tokens billed. At GPT-5.4-mini pricing, the full experimental cost is approximately \$58 (\$2 per project), confirming practical cost-effectiveness. Backward slicing further reduces prompt length by $\approx$25\%, concentrating tokens on branch-relevant context and improving the coverage-per-token ratio over naive full-context prompting.

\paragraph{Runtime.}
Using QC3-30B as the backbone, SymPrompt finishes in 17 hours generating 4,823 tests ($\approx$1.6 per MUT) via a single-pass strategy. HITS and Panta require 22 and 26 hours, producing 7,418 and 8,134 tests respectively. \ourmethod{} completes in 25 hours with 8,876 tests ($\approx$3.0 per MUT), as backward slicing is triggered selectively only upon coverage stagnation rather than at every iteration.

\paragraph{Ablation Anomalies.}
While both BS and CS yield consistent average gains, Table~\ref{tab:ablation} 
reveals two classes of per-project anomalies worth discussion.

\emph{Cases where w/o BS outperforms \ourmethod{}.}
On JXml ($-$9.76\,pp) and JDatabind ($-$8.70\,pp), removing backward slicing improves coverage. Manual inspection indicates that in these projects, slices occasionally remove type declarations needed for mock construction, causing the LLM to fall back on simpler test patterns that happen to cover more branches. This is consistent with the coarser control flows noted for JXml in RQ3. On Collections and Compress, where branches are governed primarily by value-range conditions rather than cross-method state, aggressive slicing removes auxiliary boundary context that—while not strictly necessary for reachability—provides useful cues for the LLM.

\emph{Cases where w/o CS outperforms \ourmethod{}.}
On Lang ($-$10.90\,pp) and JxPath ($-$6.12\,pp), removing constraint hints improves coverage. We attribute this to over-specification: when branch conditions are relatively straightforward, injecting explicit constraint hints introduces unnecessary prior assumptions that bias the LLM away from simpler, effective test patterns it would otherwise discover autonomously.

Both anomaly classes point to the same root cause: the current design applies BS and CS uniformly, without adapting to branch complexity. Designing \emph{adaptive} strategies—activating each component selectively based on dependency depth and condition complexity—remains the primary direction for future work.

\paragraph{Design Implications.}
Our results suggest a synergistic relationship between structural guidance and model reasoning capacity: CS lowers the reasoning barrier for cross-method preconditions, while larger models are better positioned to exploit that guidance. This implies that future improvements in LLM reasoning ability will further amplify the value of structured test generation frameworks such as \ourmethod{}.

\paragraph{Scalability.}
Backward slicing and constraint extraction introduce preprocessing overhead proportional to the inter-procedural dependency graph. The average preprocessing time per focal method is 1.2\,s in our evaluation, which is acceptable for medium-scale projects. Incremental or on-demand slicing may be required for large-scale industrial systems.
